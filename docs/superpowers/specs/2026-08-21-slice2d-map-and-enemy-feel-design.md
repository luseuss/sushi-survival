# 슬라이스 2d: 무한 타일 맵 + 적 뭉침 방지·넉백 설계

- 상태: 승인됨 (브레인스토밍 완료, 구현 계획 대기)
- 선행 문서: [슬라이스 2c 런 구조](2026-08-20-slice2c-run-structure-design.md)
- 기획서 압축본: [CLAUDE.md](../../../CLAUDE.md)
- 날짜: 2026-08-21

## 배경

슬라이스 2c까지 한 판이 완결되는 구조가 갖춰졌다. 이제 그 5분 동안의 플레이 감각을
다듬는다. 사용자가 직접 지적한 두 가지가 대상이다.

1. **바닥이 단색 이미지 한 장**이라 이동해도 움직이는 느낌이 없다.
2. **적이 한 덩어리로 뭉친다.** 서로를 통과하는 유령처럼 보이고, 때려도 반응이 없다.

## 발견 사항: 카메라가 원근 투영

씬의 메인 카메라가 `orthographic: 0`(Perspective, `field of view: 60`)으로
설정되어 있다. 2D 픽셀아트에서는 직교 투영이어야 한다.

지금까지는 모든 오브젝트가 z=0에 있어 큰 문제가 드러나지 않았으나, 원근 투영에서는
화면 가장자리로 갈수록 스프라이트가 기울어 보이고 픽셀 크기가 일정하지 않다.
타일을 격자로 촘촘히 깔면 이 왜곡이 눈에 띄게 된다.

체크박스 하나로 고쳐지므로 이번 슬라이스 준비 단계에 포함한다.

## 규모 계산

| 항목 | 값 |
|---|---|
| 타일 크기 | 32px, PPU 100 → **0.32 월드 유닛** |
| 카메라 | Orthographic Size 5 → 세로 10유닛, 16:9에서 가로 약 17.8유닛 |
| 화면에 보이는 타일 | 약 **55 × 31 ≈ 1,700개** |

이 숫자가 렌더링 방식을 결정한다. 타일 하나당 GameObject를 두는 방식은 성립하지
않는다.

## 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 맵 렌더링 | Unity Tilemap + 청크 스트리밍 |
| 타일 선택 | 좌표 해시 기반 **결정론적** 생성 |
| 기본 잔디 | `바닥 테두리 x.png` (테두리 없는 16종) |
| 유적 | 3×3 한 덩어리로 이어짐 → 패치 단위 배치 |
| 사막 | 낱개 타일로 사용 |
| 뭉침 방지 | 분리 힘(separation) — Kinematic 유지 |
| 넉백 | `TakeDamage`에 공격자 위치를 넘겨 방향 계산 |
| 이동 주체 | `EnemyAI` 한 곳에서만 `MovePosition` 호출 |

## 접근법 비교

### 맵 렌더링 (승인됨: A안)

| 안 | 설명 | 채택 |
|---|---|---|
| A. Unity Tilemap + 청크 스트리밍 | `Tilemap.SetTile`로 채우고 비운다 | **채택** |
| B. 타일마다 GameObject + SpriteRenderer | — | 기각 |
| C. 청크마다 Texture2D 런타임 합성 | — | 기각 |

A안 채택 근거:
- `com.unity.modules.tilemap`이 **이미 설치되어 있다**. 추가 패키지가 필요 없다.
- Tilemap이 내부적으로 배칭하므로 1,700타일도 드로우콜 몇 개로 처리된다.
- Tile 에셋은 런타임에 `ScriptableObject.CreateInstance<Tile>()`로 스프라이트마다
  하나씩 만들면 되므로, 에디터용 Tile Palette 패키지(`com.unity.2d.tilemap`)를
  설치할 필요가 없다.

B안은 1,700개 이상의 GameObject를 매 프레임 관리해야 해서, 풀링하더라도 부스 데모
사양에서 프레임이 떨어질 위험이 크다. C안은 드로우콜은 최소지만 구현 복잡도와
메모리 관리 부담이 이 규모에 비해 과하다.

### 뭉침 방지 (승인됨: A안)

| 안 | 설명 | 채택 |
|---|---|---|
| A. 분리 힘(separation) 추가 | 주변 적의 반대 방향 벡터를 이동에 더한다 | **채택** |
| B. Dynamic Rigidbody 물리 충돌 | 콜라이더가 서로 밀어내게 한다 | 기각 |
| C. 스폰 위치만 흩뿌리기 | — | 기각 |

A안 채택 근거:
- 슬라이스 1에서 접촉 데미지 버그를 겪으며 맞춘 Kinematic +
  `Use Full Kinematic Contacts` 설정을 그대로 유지한다.
- 세기 값 하나로 "얼마나 안 겹치게 할지"를 튜닝할 수 있다.

B안은 `MovePosition`이 Dynamic에서 권장되지 않아 속도 기반으로 다시 짜야 하고,
플레이어와도 밀리며, 밀림이 누적되어 적이 엉뚱한 위치로 튕겨나간다. 안정화된 물리
설정을 뒤집는 위험이 이득보다 크다.

C안은 근본 해결이 아니다. 적은 결국 플레이어로 수렴하므로 다시 뭉친다.

## 아키텍처

### 결정론적 타일 생성

**같은 좌표는 언제나 같은 타일을 내놓아야 한다.** 무작위로 그때그때 뽑으면 왔던
자리로 되돌아갔을 때 바닥이 딴판으로 바뀌어 어지럽고, 무한 맵이 주는 "공간이
실재한다"는 감각이 깨진다. 청크를 버렸다가 다시 만들어도 결과가 같아야 한다.

좌표와 시드를 해시해 타일을 고르는 **순수 함수**로 처리한다. 이 로직이 이번
슬라이스의 주된 유닛 테스트 대상이다.

배치 규칙:

| 종류 | 단위 | 빈도 |
|---|---|---|
| 잔디 (16종) | 낱개 | 기본 |
| 사막 (4종) | 낱개 | 약 8% |
| 유적 (3×3 덩어리) | **패치** | 패치 격자에서 약 4% |

유적은 9칸이 이어져 하나의 돌바닥 구조물을 이루므로, 3칸 단위 패치 격자에서
해시를 돌려 배치 여부를 정하고, 패치 안의 위치(0~8)로 어느 타일인지 결정한다.
사막과 유적이 겹치면 유적이 이긴다.

### 청크 스트리밍

카메라 위치를 기준으로 필요한 청크 집합을 계산하고, 새로 필요해진 청크는 채우고
멀어진 청크는 비운다. 청크 크기는 인스펙터 노출 값으로 두고 16×16 타일로 시작한다.

Tilemap은 하나만 쓰고, 청크는 "어느 좌표 범위를 채웠는지"를 관리하는 단위로만
존재한다. Tilemap이 이미 희소 저장을 하므로 청크마다 별도 Tilemap을 둘 이유가 없다.

### 적 이동 통합

추격·분리·넉백 세 가지가 모두 위치를 바꾸는데, **`MovePosition`을 호출하는 곳이
둘 이상이면 서로 덮어쓴다.** `EnemyAI`가 세 벡터를 합쳐 한 번만 이동시키고, 계산
자체는 순수 함수로 분리한다.

```
최종 이동 = (추격 방향 × 이동속도 + 분리 방향 × 분리세기 + 넉백속도) × deltaTime
```

분리 벡터는 매 프레임이 아니라 0.1초마다 갱신한다. 천천히 변해도 충분하고, 적이
많을 때 물리 쿼리 비용이 크다. 조회는 `Physics2D.OverlapCircleNonAlloc`으로 할당
없이 수행하며, 버퍼는 8마리로 제한한다 — 가장 가까운 몇 마리만 고려해도 겹침을
막는 데 충분하다.

### 넉백

현재 `EnemyBase.TakeDamage(float damage)`에는 공격자 정보가 없어 밀어낼 방향을 알
수 없다. `TakeDamage(float damage, Vector2 sourcePosition)`으로 바꾸고 호출하는 두
곳에서 위치를 넘긴다.

| 호출처 | 넘길 위치 |
|---|---|
| `EggFanWeapon.Attack()` | 플레이어(무기 오브젝트) 위치 |
| `Projectile.OnTriggerEnter2D()` | 투사체 위치 |

적은 넉백 속도를 보관하다가 시간에 따라 감쇠시키고, `EnemyAI`가 이동에 더한다.

**중형몹과 보스는 덜 밀려야 한다.** `MonsterData`에 `knockbackResistance`(0~1)를
추가한다. 잡몹 0, 중형몹 0.7로 시작한다. 저항이 없으면 체력 200짜리 중형몹이 총알을
맞을 때마다 뒤로 날아가 위협감이 사라진다.

무한 맵이라 벽이 없으므로, 넉백으로 적이 지형 밖으로 밀려나는 문제는 없다.

| 항목 | 초기값 |
|---|---|
| 청크 크기 | 16 × 16 타일 |
| 청크 유지 반경 | 카메라 기준 2청크 |
| 사막 타일 확률 | 8% |
| 유적 패치 확률 | 4% |
| 분리 감지 반경 | 0.6 유닛 |
| 분리 세기 | 이동속도의 1.5배 |
| 분리 갱신 주기 | 0.1초 |
| 넉백 세기 | 3 (유닛/초) |
| 넉백 감쇠 | 초당 12 |
| 넉백 저항 — 잡몹 / 중형몹 | 0 / 0.7 |

## 구현 순서

1. **준비** — 카메라 Orthographic 전환, 타일 스프라이트 슬라이스
2. **무한 타일 맵** — 해시 생성기, 타일 선택 로직, 청크 스트리밍
3. **적 분리 + 넉백** — 순수 로직, `MonsterData` 확장, `EnemyAI` 통합

1·3은 서로 독립적이므로, 맵에서 막히더라도 적 개선은 따로 진행할 수 있다.

## 테스트 전략

기존과 동일하다. 순수 로직은 EditMode 유닛 테스트로 TDD하고, MonoBehaviour 통합
동작은 Play 모드 수동 테스트로 확인한다.

이번 슬라이스에서 유닛 테스트 대상이 되는 순수 로직:

- `TileHash.Hash(int x, int y, int seed)` — 같은 입력은 같은 출력, 좌표가 다르면
  값이 흩어짐, 음수 좌표에서도 동작
- `TilePicker.Pick(int x, int y, int seed, TileMixConfig)` — 종류·인덱스 결정,
  결정론성, 유적 패치가 3×3으로 이어짐, 유적이 사막을 이김
- `ChunkGrid.WorldToChunk` / `GetRequiredChunks` — 필요한 청크 집합 계산
- `SeparationLogic.ComputeSeparation(self, neighbors, radius)` — 이웃이 없으면
  영벡터, 가까울수록 강하게, 정확히 겹쳤을 때 NaN이 나오지 않음
- `KnockbackLogic.ComputeImpulse(sourcePos, targetPos, force, resistance)` —
  공격자 반대 방향, 저항 1이면 0, 정확히 겹쳤을 때 NaN 방지
- `KnockbackLogic.Decay(velocity, decayPerSecond, deltaTime)` — 0 아래로 안 감

## 에러 처리 / 엣지 케이스

- 적 두 마리가 **정확히 같은 위치**에 있으면 분리 방향 계산에서 0으로 나누게 된다.
  이 경우 영벡터를 돌려주고, 스폰 위치가 완전히 겹치는 일이 반복되면 다음 프레임에
  자연히 풀린다.
- 넉백 방향도 공격자와 적이 정확히 겹치면 같은 문제가 생긴다. 동일하게 영벡터로
  처리한다.
- 카메라가 매우 빠르게 이동하면 한 프레임에 여러 청크가 필요해질 수 있다. 필요한
  청크를 전부 계산해 한 번에 채운다.
- 타일 스프라이트가 하나도 할당되지 않으면 맵이 비어 보인다. 시작 시
  `Debug.LogError`로 명확히 알린다.
- 런을 재시작하면 씬이 다시 로드되므로 맵도 처음부터 생성된다. 시드를 고정값으로
  두면 매 판 같은 맵이, 랜덤으로 두면 매 판 다른 맵이 된다. **시드는 인스펙터
  노출로 두고 기본은 매 판 랜덤**으로 한다(부스 데모에서 매번 같은 바닥이면
  단조롭다).
