## 배경

슬라이스 2b까지 캐릭터를 고르고, 싸우고, 레벨업해서 강해지는 루프가 완성되었다.
그러나 **런에 구조가 없다** — 타이머도 없고 난이도 상승도 없으며, 죽지 않으면
영원히 끝나지 않는다. 결과 화면도 없어서 한 판이 끝나도 다시 시작할 방법이 없다.

이 슬라이스는 기획서의 웨이브 타임라인을 구현해 **5분짜리 한 판을 완결**시킨다.

## 범위에서 제외하고 다음으로 미루는 것

**보스는 이번 슬라이스에 포함하지 않는다.** 보스 아트(대기 5·이동 6·공격 패턴
13·소환 패턴 13프레임 + 이펙트 2종)는 이미 준비되어 있으나, 패턴 동작·페이즈
전환·체력 4000 밸런스가 전부 미확정이라 자체 설계 논의가 필요하다.

**슬라이스 2d로 별도 기록해 둔 항목** (이번 범위 아님):
- 무한 타일 맵 — `바닥.png`(16타일), `바닥 테두리 x.png`(16타일),
  `유적 바닥 (깨짐)`/`(깨짐x)`(각 9타일), `사막 바닥`(4타일)을 32×32로 잘라
  카메라를 따라 청크 단위로 생성·재활용
- 적 분리(뭉침 방지) + 피격 시 넉백

## 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 타임라인 구성 | 씬 레벨 이벤트 배열 (`WaveDirector`의 인스펙터 필드) |
| 5:00 도달 시 | 보스가 없는 동안은 **생존 성공 = 승리**로 처리 |
| 런 상태 | `CharacterSelect / Playing / Result` + `RunOutcome { Victory, Defeat }` |
| 재시작 | **씬 리로드** (`SceneManager.LoadScene`) |
| 결과 화면 표시 항목 | 생존 시간, 도달 레벨, 처치 수, 획득 증강 목록 |
| 젬 | 3종(흰 1XP / 갈 5XP / 금 10XP)으로 확장 |
| 중형몹 | 체력 200 / 접촉 12 / 이동 1.2, 금색 젬 드롭, 2:00·4:00 등장 |

## 접근법 비교

### 웨이브 타임라인 구성 (승인됨: A안)

| 안 | 설명 | 채택 |
|---|---|---|
| A. 씬 레벨 이벤트 배열 | `WaveDirector`가 `{시각, 풀, 마리 수}` 배열을 인스펙터에 보유 | **채택** |
| B. ScriptableObject 타임라인 에셋 | 프로젝트의 다른 데이터와 일관됨 | 기각 |
| C. 코루틴 시퀀스 | `yield return new WaitForSeconds(120)` | 기각 |

**A안 채택의 결정적 이유:** 스폰 대상인 `GameObjectPool`은 **씬 오브젝트**라서
ScriptableObject가 참조할 수 없다. 이 프로젝트에서 이미 두 번 부딪힌 제약이다
(`EnemyBase.xpGemPool`, `ShrimpRifleWeapon.projectilePool` 모두 런타임 주입으로
우회했다). 타임라인 설정을 씬 레벨에 두면 이 문제가 아예 발생하지 않는다.

B안은 프리팹을 담고 런타임에 풀을 찾아 매칭하는 우회가 필요해져 오히려 복잡해진다.
C안은 수치를 바꾸려면 코드를 고쳐야 해서, 기획서의 "플레이테스트 중 빠르게 튜닝
가능하게" 요구와 어긋난다.

### 재시작 처리 (승인됨: A안)

결과 화면에서 캐릭터 선택으로 돌아가려면 런의 모든 흔적을 지워야 한다 — 플레이어
오브젝트, 살아있는 적, 바닥의 젬, 날아가는 투사체, 레벨·경험치, 누적 증강,
처치 수, 타이머.

| 안 | 설명 | 채택 |
|---|---|---|
| A. 씬 리로드 | `SceneManager.LoadScene(현재 씬)` | **채택** |
| B. 수동 초기화 | 씬을 유지한 채 상태를 하나씩 되돌림 | 기각 |

A안 채택 근거:
- 세이브도 메타 진행도 없는 원런 구조라 다음 판으로 넘길 상태가 **하나도 없다**.
- 씬이 작아 로드가 거의 즉각적이다(부스 데모에서 문제되지 않는다).
- 초기화 누락 버그가 원천적으로 불가능하다. B안은 목록을 하나라도 빠뜨리면 조용히
  새는 버그가 되며, 앞으로 보스·대화가 붙을수록 그 목록이 계속 길어진다.

슬라이스 2a에서 택한 "단일 씬 + UI 패널" 구조와 모순되지 않는다 — 씬은 여전히
하나이고, 재시작할 때만 그 씬을 다시 열 뿐이다.

## 아키텍처

### WaveDirector

씬에 배치되는 컴포넌트로, 런 경과 시간을 보며 예약된 스폰 이벤트를 발화한다.

```
WaveEvent { float timeSeconds; GameObjectPool pool; int count; }
WaveDirector { WaveEvent[] events; }
```

기본 이벤트 구성:

| 시각 | 내용 |
|---|---|
| 2:00 | 중형몹 1마리 |
| 4:00 | 중형몹 1마리 |

잡몹 지속 스폰은 기존 `EnemySpawner`가 계속 담당한다. 중형몹은 잡을 때까지
사라지지 않는다(기획서: "2:00–4:00 잡몹 지속 + 중형몹 유지").

**이벤트 발화 판정은 순수 함수로 분리한다.** 프레임 간격 때문에 이벤트가
누락되거나 두 번 발화하는 것은 흔한 버그이므로, "이전 프레임 시각 ~ 현재 시각
사이에 걸친 이벤트"를 골라내는 로직을 유닛 테스트로 검증한다. 한 프레임에 여러
이벤트가 걸리는 경우(큰 델타)도 포함한다.

### 런 상태와 타이머

`GameManager`가 `ElapsedTime`을 보유하고 `Playing` 상태에서만 증가시킨다.
`runDuration`(기본 300초)에 도달하면 승리, 체력 0이면 패배로 런을 끝낸다.

기존 `RunState.GameOver`를 `Result`로 바꾸고 `RunOutcome { Victory, Defeat }`를
함께 둔다. 현재 이름으로는 승리 종료를 표현할 수 없다.

**정리 대상:** `GameManager.IsGameOver` 프로퍼티는 선언만 되어 있고 아무데서도
사용되지 않는 죽은 코드다. 이번에 제거한다.

화면 상단에 남은 시간을 표시한다. `"4:23"` 형식 변환은 순수 함수로 분리해
테스트한다 — 60초 경계에서 `4:60`이 나오거나 음수에서 깨지는 것이 흔한 실수다.

### 기록 수집

| 항목 | 소유자 |
|---|---|
| 생존 시간 | `GameManager.ElapsedTime` |
| 처치 수 | `GameManager` 카운터 — `EnemyBase.Die()`에서 알린다 |
| 도달 레벨 | `LevelSystem.CurrentLevel` (이미 존재) |
| 획득 증강 | `LevelSystem`이 고른 순서대로 보관하는 목록 (신규) |

`EnemyBase`가 `GameManager.Instance`를 통해 처치를 알리는 것은 `XPGem`이 이미
쓰고 있는 패턴과 동일하다.

### 결과 화면

`ResultPanel`이 승리/패배 문구와 위 네 항목을 표시한다. 증강은 같은 것을 여러 번
고를 수 있으므로 **아이콘 + `x3`** 형태로 묶어서 보여준다. 아이콘 10개가 그대로
늘어서면 읽기 어렵다.

버튼은 "다시 하기" 하나이며, 누르면 씬을 리로드해 캐릭터 선택으로 돌아간다.

### 젬 3종화

젬 프리팹 3개(흰 1XP / 갈 5XP / 금 10XP)와 각각의 풀을 만든다.
`XPGemPoolSet` 컴포넌트가 `XPGemType → GameObjectPool` 매핑을 보유하고,
`EnemyBase`는 풀 하나 대신 이 세트를 주입받아 `MonsterData.xpGemDrop`에 맞는
풀을 고른다.

`MonsterData.xpGemDrop` 필드는 슬라이스 1부터 존재했으나 사용되지 않고 있었다.
이번에 실제로 연결한다.

### 몬스터 수치

| | 체력 | 접촉 데미지 | 이동속도 | 젬 |
|---|---|---|---|---|
| 잡몹 A (검은 초밥 병사) | 12 | 5 | 2 | 흰 (1XP) |
| 잡몹 B (캘리포니아롤) | 20 | 5 | 1.5 | 흰 (1XP) |
| 중형몹 | 200 | 12 | 1.2 | 금 (10XP) |

중형몹은 잡몹 아트(50×50)의 2배인 100×100이며 이동 5프레임만 있으므로, 잡몹과
동일한 단순 추적형으로 구현한다. 별도 공격 패턴은 없다.

## 구현 순서

각 단계가 끝날 때마다 플레이 가능한 상태가 되도록 나눈다.

1. **타이머 + 런 종료** — 경과 시간, 5:00 승리, 상태 전환, 타이머 UI.
   결과 화면 없이 로그로만 확인한다.
2. **결과 화면 + 재시작** — 기록 수집(처치 수·증강 목록), `ResultPanel`,
   씬 리로드.
3. **젬 3종화 + 중형몹 + 타임라인** — 젬 풀 세트, 중형몹 프리팹, `WaveDirector`.

## 테스트 전략

기존과 동일하다. 순수 로직은 EditMode 유닛 테스트로 TDD하고, MonoBehaviour 통합
동작은 Play 모드 수동 테스트로 확인한다.

이번 슬라이스에서 유닛 테스트 대상이 되는 순수 로직:

- `RunClock.FormatRemaining(elapsed, duration)` — `"4:23"` 형식, 60초 경계와
  음수·초과 처리
- `WaveSchedule.GetDueEvents(previousTime, currentTime, events)` — 프레임 구간에
  걸린 이벤트 선별, 중복 발화·누락 방지, 한 프레임 다중 발화
- `AugmentTally.Summarize(pickedList)` — 획득 증강을 `(데이터, 개수)`로 묶기

## 에러 처리 / 엣지 케이스

- 레벨업 팝업이 열린 채(`Time.timeScale = 0`) 런이 끝나는 경우에도 `timeScale`을
  반드시 1로 복구한다. 슬라이스 2b에서 사망 경로는 처리했으나, 이번에 추가되는
  **승리 경로에도 같은 복구가 필요하다.**
- 승리와 패배가 같은 프레임에 성립할 수 있다(5:00 도달과 동시에 사망). 먼저
  성립한 것 하나만 처리하고, 이후 상태 전환은 무시한다.
- 결과 화면이 뜬 뒤에는 경험치 획득·레벨업·적 스폰이 모두 멈춰야 한다.
- `WaveDirector`의 이벤트 시각이 `runDuration`보다 뒤면 영원히 발화되지 않는다.
  설정 실수이므로 시작 시 경고를 남긴다.
- 중형몹이 살아있는 상태로 5:00에 도달해도 승리로 처리한다(기획서의 승리 조건은
  시간 도달이며, 이번 슬라이스에서는 보스가 없다).
