# 슬라이스 2a: 캐릭터 선택 + 간장새우(투사체 무기) 설계

- 상태: 승인됨 (브레인스토밍 완료, 구현 계획 대기)
- 선행 문서: [슬라이스 1 코어 아키텍처 설계](2026-08-19-core-architecture-design.md)
- 기획서 압축본: [CLAUDE.md](../../../CLAUDE.md)
- 날짜: 2026-08-19

## 배경

슬라이스 1에서 계란 캐릭터 하나로 코어 루프(이동 → 자동공격 → 처치 → 젬 획득 →
피격 → 사망)를 완성했다. 이 문서는 두 번째 캐릭터인 간장새우를 플레이 가능하게
만드는 데 필요한 설계를 다룬다.

간장새우는 원거리 투사체 무기를 쓰는데, 현재 프로젝트에는 투사체 개념이 전혀
없다. 또한 캐릭터가 둘 이상이 되면 "어느 캐릭터로 플레이할지" 고르는 흐름이
필요하다. 두 가지 모두 이후 이나리·보스 패턴·레벨업 시스템이 딛고 설 기반이므로,
즉흥적으로 붙이지 않고 이 문서에서 구조를 정한다.

## 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 씬 구조 | 단일 씬 + UI 패널 전환 (별도 씬 분리 안 함) |
| 캐릭터 교체 | 캐릭터 선택 화면을 지금 구현 |
| 이나리 | 선택 화면에 잠김(회색) 상태로 표시, 선택 불가 |
| 캐릭터 표현 | 캐릭터 종류별로 프리팹을 따로 만든다 |
| 무기 코드 | `WeaponBase` 추상 클래스로 공통부 추출 |
| 라이플 방향 | 시선 방향 8방향 회전 (좌우 반전 아님) |

## 접근법 비교

### 씬 구조 (승인됨: A안)

| 안 | 설명 | 채택 |
|---|---|---|
| A. 단일 씬 + UI 패널 | 선택/게임/결과를 한 씬에서 패널 토글로 전환 | **채택** |
| B. 별도 씬 분리 | `CharacterSelect` 씬 → `Game` 씬 | 기각 |
| C. 영속 매니저 + 씬 분리 | B + DontDestroyOnLoad 매니저 | 기각 — 이 규모에 과함 |

A안 채택 근거:
- 코어 루프가 `캐릭터선택 → 대화#1 → 게임 → 대화#2 → 결과 → 캐릭터선택`인데,
  대화와 결과 화면도 전부 같은 방식의 오버레이라 이후 작업이 자연스럽게 이어진다.
- 씬 로드가 없어 부스 데모에서 재시작이 즉각적이다.
- 선택한 `CharacterData`를 같은 씬 안에서 그대로 넘기면 되므로 씬 간 전달
  배선(static 홀더/전용 SO)이 불필요하다.
- 세이브도 메타 진행도 없는 원런 구조라 씬 분리로 얻는 이점이 작다.

## 아키텍처

### 런타임 스폰으로 인한 파급

현재 `CameraFollow`, `EnemySpawner`, `GameManager`는 모두 "씬 시작 시점에
플레이어가 이미 존재한다"고 가정한다. 선택 화면이 생기면 플레이어는 선택 이후에
생성되므로 셋 다 수정이 필요하다. 이것이 이 슬라이스에서 가장 파급이 큰 변경이다.

| 컴포넌트 | 변경 내용 |
|---|---|
| `GameManager` | 런 상태(`CharacterSelect` / `Playing` / `GameOver`) 보유, `StartRun(CharacterData)`에서 스폰과 배선 수행 |
| `PlayerSpawner` (신규) | `CharacterData.playerPrefab`을 생성하고 생성된 오브젝트를 돌려준다 |
| `CameraFollow` | `SetTarget(Transform)` 추가. 시작 시점에 대상이 없어도 에러를 내지 않는다 |
| `EnemySpawner` | `StartSpawning(Transform player)` 추가. 선택 화면 동안에는 스폰하지 않는다 |
| `CharacterData` | `playerPrefab` 필드 추가 |
| `PlayerController` | `CharacterAnimator`를 선택적 의존성으로 변경 (아래 "간장새우 아트 제약" 참고) |

`EnemyAI`와 `XPGem`은 `OnEnable`에서 `FindGameObjectWithTag("Player")`로 대상을
찾으므로, 플레이어가 먼저 생성되기만 하면 수정 없이 동작한다.

### 캐릭터 표현: 종류별 프리팹

캐릭터마다 무기와 애니메이터가 다르므로, 하나의 프리팹에서 스프라이트와 데이터를
런타임에 갈아끼우는 방식은 복잡하다. 대신 캐릭터 종류별로 완전히 구성된 프리팹을
만들고(`EggPlayer`, `ShrimpPlayer`), `CharacterData`가 자기 프리팹을 가리킨다.
선택 UI는 `CharacterData`만 넘기면 되고, 스포너는 그 안의 프리팹을 생성한다.

### 무기 코드 구조

현재 `EggFanWeapon`은 쿨타임 타이머와 레벨별 수치 조회를 자기 안에 갖고 있다.
간장새우를 그대로 추가하면 그 로직이 복제되고, 이나리에서 또 복제된다.

```
WeaponBase (추상)          ← 쿨타임 타이머, 레벨 수치 조회, AttackAnimator 호출
├─ EggFanWeapon            ← 부채꼴 판정 (기존 로직 이동)
└─ ShrimpRifleWeapon       ← 투사체 발사
```

`WeaponBase`가 매 프레임 쿨타임을 깎고, 준비되면 `AttackAnimator`를 트리거한 뒤
추상 메서드 `Attack()`을 호출한다. 각 무기는 `Attack()`만 구현한다.

### 투사체

기존 `GameObjectPool`을 그대로 재사용한다. `Projectile` 컴포넌트가 방향, 속도,
데미지, 관통 수, 수명을 가진다.

- 발사: `ShrimpRifleWeapon`이 풀에서 꺼내 `Initialize(...)`로 값을 주입한다.
- 이동: 매 프레임 지정된 방향으로 직진한다.
- 적중: `EnemyBase`에 데미지를 주고 적중 수를 센다.
- 소멸: 적중 수가 관통 수를 넘거나, 수명이 다하면 풀로 반환한다.

관통 수의 의미는 기획서를 따른다 — Lv1 관통 0은 "1체만 타격 후 소멸"이다.
따라서 소멸 조건은 `적중 수 > 관통 수`다.

### 무기 방향

`WeaponVisual`에 방향 모드를 추가한다.

| 모드 | 사용 캐릭터 | 동작 |
|---|---|---|
| `FlipOnly` | 계란 (양산) | 좌우 반전만. 현재 동작 유지 |
| `RotateToFacing` | 간장새우 (라이플) | 시선 방향으로 회전하고 캐릭터 주위를 공전 |

기획서에 "간장새우·이나리는 이 방향 시스템을 그대로 공격 방향에 사용"이라고
명시되어 있으므로 8방향 회전이 맞다.

### 캐릭터 선택 UI

Canvas에 버튼 3개를 미리 배치하고, 각 버튼이 `CharacterData`를 하나씩 참조한다.
동적 생성은 하지 않는다 — 캐릭터가 3종으로 고정이고, 인스펙터에서 배선을 눈으로
확인할 수 있는 편이 이 규모에서 유리하다.

- 이나리 버튼은 `interactable = false`로 두고 회색 처리한다.
- 초상화는 `CharacterData.portraitSprite`를 사용한다
  (계란 `new 계란.png`, 간장새우 `new 간장새우.png`, 이나리 `이나리.png`).
- 버튼 클릭 → `GameManager.StartRun(characterData)` 호출 → 선택 패널 비활성화.

## 간장새우 아트 제약

간장새우의 아트는 세 장뿐이다: `new 간장새우.png`(캐릭터), `라이플.png`(무기),
`간장 총알.png`(투사체). **계란과 달리 대기·걷기 스프라이트 시트가 없다.**

따라서 이번 슬라이스에서 간장새우는 정지 스프라이트 한 장으로 구현한다.
`CharacterAnimator`는 붙이지 않으며, 걷기 애니메이션이 없다는 점을 알려진 제약으로
받아들인다. 이후 아트가 나오면 슬라이스 1에서 확립한 규약(Idle/Move 2상태 +
`IsMoving` bool)대로 클립만 만들어 끼우면 되고, 코드 변경은 필요 없다.

이를 위해 `PlayerController`의 `[RequireComponent(typeof(CharacterAnimator))]`를
제거하고, `CharacterAnimator`를 **선택적 의존성**으로 바꾼다. 컴포넌트가 없으면
이동 애니메이션 호출을 건너뛴다. 이 제약을 두지 않으면 몸통 애니메이션 아트가
없는 캐릭터는 파라미터가 비어 있는 애니메이터를 억지로 달아야 하고, Unity가 매
프레임 경고를 뱉는다.

## 수치

기획서의 간장 소총 값을 `WeaponData` 에셋에 그대로 입력한다.

| Lv | 데미지 | 관통 | 쿨타임 |
|---|---|---|---|
| 1 | 12 | 0 (1체) | 0.8초 |
| 2 | 14 | 1체 | 0.75초 |
| 3 | 17 | 1체 | 0.7초 |
| 4(MAX) | 20 | 2체 | 0.65초 |

투사체 속도와 수명은 기획서에 없는 값이므로 인스펙터 노출 값으로 두고
플레이테스트로 조정한다. 초기값은 속도 10, 수명 3초로 시작한다.

간장새우의 기본 이동속도와 체력은 계란과 동일하게 시작한다(기획서에 캐릭터별
차등 수치가 명시되어 있지 않다). 플레이테스트 후 차등이 필요하면 그때
`CharacterData`에서 조정한다.

## 구현 순서

각 단계가 끝날 때마다 플레이 가능한 상태가 되도록 나눈다.

1. **`WeaponBase` 리팩터** — 기능 변화 없음. 계란이 이전과 동일하게 동작하는지만
   확인한다.
2. **캐릭터 선택 + 스폰 흐름** — 계란 하나만 있는 선택 화면에서 선택하면 게임이
   시작된다. 런타임 스폰 파급(카메라, 적 스포너, 게임매니저)을 이 단계에서 모두
   해결한다.
3. **간장새우 추가** — 캐릭터 프리팹, 라이플 회전, 투사체와 관통.

## 테스트 전략

슬라이스 1과 동일하다. 순수 로직은 EditMode 유닛 테스트로 TDD하고, MonoBehaviour
통합 동작은 Play 모드 수동 테스트로 확인한다.

이번 슬라이스에서 유닛 테스트 대상이 되는 순수 로직:

- `ProjectileLogic.ShouldDespawn(적중 수, 관통 수)`
- `WeaponVisualLogic.ComputeRotationDegrees(시선 벡터)`
- `WeaponVisualLogic.ComputeOrbitOffset(시선 벡터, 거리)`
- `WeaponCooldown` — 쿨타임 경과·발사 준비 판정 (`WeaponBase`에서 분리)

## 에러 처리 / 엣지 케이스

- `CharacterData.playerPrefab`이 비어 있으면 `PlayerSpawner`가 `Debug.LogError`로
  명확히 알리고 스폰하지 않는다. 조용히 폴백하지 않는다.
- 선택 화면 상태에서는 `EnemySpawner`가 스폰하지 않으므로, 플레이어 없이 적이
  생성되어 `FindGameObjectWithTag` 실패로 이어지는 상황이 발생하지 않는다.
- 투사체가 아무것도 맞히지 못한 경우 수명 타이머로 반드시 회수된다 — 회수 누락으로
  풀이 고갈되지 않게 한다.
- `GameManager.StartRun`이 이미 `Playing` 상태에서 다시 호출되면 무시한다
  (버튼 연타로 플레이어가 두 번 생성되는 것을 막는다).

## 범위 밖 (이후 슬라이스)

- 이나리 캐릭터 구현 (아트 부족)
- 레벨업 3택 팝업, 무기 레벨 상승 (현재 무기 레벨은 인스펙터 고정값)
- 중형몹, 보스, 웨이브 타임라인
- 증강 10종 실제 적용
- 호감도 대화, 결과 화면
- 간장새우 걷기/대기 애니메이션 (아트 나온 뒤)
